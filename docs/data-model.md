# Pharmco POS — Data model

Two schemas: **master** (lifecycle/Auth) + **per-tenant** (business data).
DDL lives in the ordered chains `db/master/` (001 → 003 → 006) and
`db/tenant/` (002 → 004 → 005 → 007) — both are executed against a live
Postgres in CI/validation (the exact round-trip lives in `.tmp/smoke.sql`).

## Master (schema `public`)

| table | purpose |
|---|---|
| `tenants` | code, name, owner phone, license claim + expiry, schema name, status |
| `users` | tenant staff (admin/pharmacist/cashier), bcrypt hash; `deleted_at` soft delete (003) |
| `daraja_config` | per-tenant M-Pesa creds, AES-256-GCM encrypted, sandbox/prod switch |
| `refresh_tokens` | rotating refresh tokens (30 d) — 64-byte base64url stored SHA-256 hashed; `family_id` rotation + reuse detection (`003_refresh_tokens.sql`) |
| `tenant_events` | append-only lifecycle audit (created/provisioned/renewed/…) |

## Per-tenant (one schema per pharmacy, e.g. `tenant_pharmco_001`)

| table | purpose | notes |
|---|---|---|
| `devices` | POS terminals | `machine_id` fingerprint; license `max_terminals` counts active rows |
| `products` | catalog | `stock_qty` is **derived**, see invariant 1 |
| `sales` | invoices | `pending_verification` = offline M-Pesa fallback |
| `sale_items` | line items | qty × unit_price |
| `stock_moves` | inventory ledger | **only writer** of `products.stock_qty` |
| `outbox` | offline write queue | drained by HUB sync agent |
| `audit_logs` | insert-only log | `fillfactor=70` for append locality |

## Invariants (enforce in the app layer — acceptance-test these)

1. `products.stock_qty = COALESCE(SUM(stock_moves.qty_change), 0)` for every
   product, always. `stock_moves` is the only table that changes stock.
2. Completing a sale writes: `sales` (status `complete`) + `sale_items` rows +
   one `stock_moves(reason='sale', qty_change=-qty, ref_id=sale_id)` **in one
   transaction**, then `outbox` entries.
3. Voiding a sale writes `sales.status='voided'` + `stock_moves(reason='void',
   qty_change=+qty, ref_id=sale_id)` — never a hard delete.
4. Every local mutation bumps `sync_seq` and appends `outbox`.
5. UUID PKs everywhere; no hard deletes on synced entities (`deleted_at`).

## Invoice numbering

`INV-YYYYMMDD-NNNN`, sequence per day per tenant; generated by the HUB (single
writer) so offline invoices never collide on the LAN; cloud accepts only
monotonic numbers per tenant.

## Why no SQLCipher (deliberate)

Local SQLite mirrors the tenant's own catalog/sales — it stores **no**
credentials (refresh tokens are stored hashed server-side; M-Pesa creds never
leave the cloud). Commodity Windows disk encryption + user accounts is the MVP
boundary; SQLCipher commercial licensing (~$999/yr with performance/feature
restrictions) is not justifiable at 30 tenants.

**One exception (auth requirement):** the desktop **credential cache**
(`client/Pharmco.Client/src/Services/CredentialCache.cs`) stores offline-login
material (bcrypt password hash + DPAPI-wrapped tokens) and IS SQLCipher-encrypted
(AES-256), with its key DPAPI-wrapped at rest. The business HUB SQLite remains
unencrypted.
